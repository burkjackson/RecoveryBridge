Measured 25 Aug 2026 across 202 sessions: 48 real two-way conversations, 45 where nobody spoke, and **96 where the seeker wrote and the listener never replied**. 45. **No security headers, and no CSP at all (fixed 3 Sep 2026)** — `next.config.js` had no `headers()`. Vercel adds HSTS by default but nothing else. Added `X-Content-Type-Options: nosniff`, `Referrer-Policy: strict-origin-when-cross-origin`, `X-Frame-Options: DENY`, and `Permissions-Policy: camera=(), microphone=(), geolocation=()` on every route, plus a `Content-Security-Policy-Report-Only` header — **report-only, not enforcing**, since a full CSP touches Sentry, Supabase realtime, and the site's own inline JSON-LD, and getting one of those wrong should show up in reports before it breaks the app. Supabase's host and Sentry's ingest host are read from `NEXT_PUBLIC_SUPABASE_URL` and `NEXT_PUBLIC_SENTRY_DSN` at config-load time rather than hardcoded, so the same file works across environments; a missing or malformed value just drops that source instead of failing the build. `script-src` and `style-src` need `'unsafe-inline'` — the JSON-LD `<script type="application/ld+json">` tags on the landing page and every `app/support/*/page.tsx` are still `<script>` elements as far as CSP is concerned even though they never execute as JS, and Tailwind relies on inline styles in places. `img-src` allows `blob:` for `AvatarUpload.tsx`'s `URL.createObjectURL()` preview. Sentry's `tunnelRoute: '/monitoring'` (already configured) proxies most client Sentry traffic same-origin, but Session Replay can still talk to the ingest host directly, so it's allowed too. **To promote to enforcing:** watch Sentry's report-only violations (or a real browser's devtools console on a few page loads) for a while first — the moment nothing's getting flagged, rename the header from `Content-Security-Policy-Report-Only` to `Content-Security-Policy`.
